# 剪成成片

在本仓库根目录（这个 SKILL.md 往上三级的文件夹）里干活。先读 pipeline.yaml，只跑 stage 不大于 current_stage 的步骤，按顺序调用脚本；清单里没有的步骤不做。设置在 config.yaml，本机的路径在 config.local.yaml（写了的项覆盖 config.yaml，没有这个文件就用默认值），下面说“设置里的 xxx”都是指这两份合起来。下面 <文件夹> 是设置里 videos_root 下的 <日期_名称>/，<运行> 是 cut_audio.py 新建的 runs/<时间>/。每个脚本出错时，把它打印的原文给用户看，说明可能的原因，停下；报的是缺 ffmpeg、转写模型或 Python 库，跑 `uv run python scripts/doctor.py`，把缺的和“怎么装”给用户看。

## 找素材（第 2 步，只依赖讲稿，可以在录口播之前做）

用户说“找素材”，或者说“剪成成片”时 <文件夹>/素材/assets.json 还没有，就先做这一步（竖屏默认不做，用户说要加素材才做，见“竖屏”一节）：
- 还没有原片时跑 `uv run python scripts/prepare.py --script-only`，只按讲稿建文件夹；原片来了，第 1 步用同一个名称会接着用它。
- 跑 `prepare.py --shot-table <文件夹>`，照镜头表逐句写 <文件夹>/素材/plan.json。格式和每类的必填项见 scripts/fetch_assets.py 开头；网址从讲稿的“来源”一节取；highlight 照网页原文抄（来源页面没打开过就先不写）；第三方截图和视频都写 credit（媒体名、日期）。讲稿没有镜头表时，按句自己出，先列给用户确认。来源清单的链接就用这里写的 url（不用截图时地址栏的地址），所以 url 写原文那一页。
- 跑 `uv run python scripts/fetch_assets.py <文件夹>`。校验不过就按报错改 plan.json 重跑。然后看 素材/预览.jpg：截图清不清楚、红框框得对不对，不对就改 highlight 重跑；素材清单里注明“截图时地址栏变成了……”的，看截到的是不是这一页（被拦到验证页、往下滚换了文章的，交给用户手动或用 fallback）；注明“截图聚焦改用单屏图”的，是长图里的字和量的位置对不上，程序已经换成单屏图；图库的图和视频逐张看是不是对题（程序只取搜索结果的第一个够大的），不对题就改 query 用 `--only <id>` 重取，换几次还不对就交给用户手动。
- 把 素材清单.md 的合计和“要你手动补的”贴给用户。用户放好手动素材说“素材放好了”，再跑一遍 fetch_assets.py。手动补的文件不是从那一项 url 那一页拿的（官方 PDF、X 帖的配图、视频的帖子页），先在 plan.json 那一项写 manual_source（媒体名、日期、实际来源的网址）再跑，来源清单照它写；改 manual_source 不会重取。
- 不用程序截、不用搜，已经有现成文件的图（用户自己截的图、维基共享资源这类地方下载的照片、访谈画面截下来的图、做好的封面）写 kind “现成图片”：note 写从哪来、怎么拿；别人的图再写 url（出处那一页）和 credit，来源清单照它记，不用另写 manual_source。文件存成 素材/<id>_manual.<扩展名>。
- 自己在手动图上画框时，照截图聚焦的样子画黄框（半透明黄底、黄边 RGB 255,196,0）：推拉时程序会找出黄框、让它始终在画面里。
- 16:9 有人脸、用户说哪几句全屏出镜（不配素材、不叠小窗，镜头表写“全屏出镜”这类）：plan.json 顶上和 items 平级写 `"face": [1, 2, 41]`（这几句的句号），items 里不给它们写素材。不写 face 时每句都要有素材，没写的句子照旧报缺，不要为了过校验把漏掉的句子写进 face。
- 网站拦下程序访问时不绕过，用 fallback 或交给用户手动。

## 无人脸模式（只用声音）

不露脸、只录声音的视频（比如每周的资讯播报）用这个模式：成片是素材画面加配音、字幕和背景音乐，没有左下角人脸小窗。
- 怎么打开：原片是纯录音（m4a、wav、mp3 等，手机录音或语音备忘录）时自动打开；原片是带画面的视频但用户说不露脸、只用声音，第 1 步加 `--no-face`。inputs.json 会记 `"no_face": true`，preprocess.json 也记一份，后面的脚本都按它走。已经建好文件夹的，补跑一次 `prepare.py --video <原片> --no-face` 就会改上，再从预处理起重跑。
- 和平常不一样的只有这几处，其余步骤（转写、删语气词和重说、压停顿、复核、配素材、转场、背景音乐、自检）照常：
  - 预处理不用原片画面、不查 HDR，工作视频是黑画面，所以粗剪是黑底加字幕，给用户看时说明只听声音和看字幕。
  - 配素材时不写 work/pip.json、不看 小窗样帧.jpg、不跑 pip_track.py（它会直接停下）。
  - 草稿（compose.py --draft）里缺素材的句子放黑底“待补素材：第 N 句”，不放全屏人脸；成片自检不把它算黑屏。
  - 字幕照旧水平居中、白字黑边、中英两行，字号不变；成片自检第 4 节只写字幕位置，不查小窗。
- 成片标准里“左下角圆形小窗”这一条在这个模式下不适用，其余照成片标准。

## 没有讲稿

用户说没有讲稿时用这个模式（用一条 46 秒、没讲稿的竖屏测试片验收过：误删、漏删、切到字、爆音、字幕错字都是 0）。默认关：找得到讲稿就照下面“步骤”对照讲稿剪；prepare.py 找不到讲稿会停下，先问用户有没有讲稿，用户说没有再加 `--no-script`，不自己加。
- 怎么打开：第 1 步跑 `prepare.py --video <原片> --no-script --name <名称>`，inputs.json 记 `"no_script": true`。没有讲稿就没有默认名称，按内容起一个给用户确认。
- 和平常不一样的只有这几处，其余照常：
  - 第 4 步方案：
    1. 跑 `uv run python scripts/reading.py <文件夹>`，读 work/阅读稿.md：按 0.5 秒以上的停顿一段一行，每段带时间和字序号；段落下面“→”开头的是术语表改得到的字，判断时按改过的读。
    2. 五轮扫描：把阅读稿从头到尾读五遍，每遍只找一类，这一遍不管别的类；后面几遍遇到前面记过的字就跳过。记在 work/五轮扫描.md，每遍一节，找到的一处一行（字序号、类型、留下的是哪一遍、风险），犹豫过没删的也记一行写为什么：
       ① 重复：一句话完整说完，又完整说了一遍或几遍，说法基本一样。
       ② 说断和改口：话说到一半停下，从头再说，第二遍用不用同样的字都算这一类；换个说法、前一遍也不算说错的，归这一类。开头说了几个字就放弃、接着说的是另一句的残句也归这一类（怎么删见第 3 条）。
       ③ 口误重说：数字、名字、词本身说错了，紧跟着说对的那遍。
       ④ 英文卡壳：英文词的开头或字母重复了几次。卡壳和后面的词被转写成了一个词（比如“matmeta”）的，删不了半个词，不删，列进“待确认”给用户。
       ⑤ 语气词和口头禅：嗯、啊、呃，当口头禅用的“那个”“就是”“然后”。这一类最主观，拿不准的不删，在对话里提一句。
       这一遍顺便找说给剪辑的人听的话（“暂停一下”“这段不要录进去”“剪掉”）：连同它说不要的那段，type 写“改稿”，reason 照抄原话，风险标高，给用户确认。这是录音里说话的人自己要的，不算 Claude 自己加的改稿。
    3. 写 work/deletions.json：格式同第 4 步，每条再加 `"risk": "低"` 或 `"高"`；说断和重说必须写 `"keep": [起, 止]`：留下的那一遍里，和删掉的那段对应的那几个字（同一句话的那一截，不用框到整句末；单字卡壳的，比如“聊聊一聊”删一个“聊”，框留下的“聊一聊”）。换成删后一遍时，keep 写前一遍留下来的那几个字。没写 keep，plan_cuts.py 会停下。类型：①③ 写“重说”，②④ 写“说断”，⑤ 写“语气词”。
       - 默认删前面的、留最后完整的那一遍。第一遍开头有、后一遍没有的字（“第三件”这类编号、主语），留着，只删重复的那段。
       - 残句：开头说了几个字就停住，隔了一会儿接着说的是另一句，这几个字和后面连不成一句话，后面也没再把它说完，就整段删，类型写“说断”，keep 框接着说的那一整句（那句自己也说断了、要删的，框最后留下的那一遍），风险标“高”。和上一条分开：上一条留的是能和留下那遍连成一句的编号、主语，连不上的才是残句。比如说了“下一个是”就停住，过两秒说“先讲讲价格”，“下一个是”就是残句；说了“第三件，我们来看……”停住，再说“我们来看价格”，“第三件”能和后面连成“第三件，我们来看价格”，照上一条留着，只删“我们来看”。
       - 标“高”的只有三种：删掉的那遍里有留下那遍没有的内容（删了会丢信息）；整句或长句的重说；删完要靠前后文才读得通的。口误和改口本来就和留下那遍说法不同，只要删掉的内容留下那遍都有，就是低；转写的同音错字不算说法不同，按实际可能说的判。
       - 只有删和不删两种，没有“建议删”：拿不准是不是重说的，不删。一句话只说了一遍的，说得不顺也不删。
    4. 跑 plan_cuts.py。字序号用 `uv run python scripts/reading.py <文件夹> --tokens 起-止` 核对（它还列每个交界能不能下刀），看 plan.md 里【】框住的是不是要删的那几个字。说断或重说进了连读待定（和前后连着说、切不开），先用 --tokens 找能下刀的交界，换一种删法再跑：删后一遍、留前一遍，或者把范围挪到前后有停顿的地方，删完留下的字要和原来打算的一样；换了还进连读待定，就留给用户在连读待定里定。
    5. 自读：读 work/删后全文.md（照删完的样子一句一行，｜是删过的接缝，〔〕里是连读待定、默认不删的字），读不通、意思变了的那几条撤掉，改完重跑 plan_cuts.py；〔〕里的也读一遍，看用户选删的话通不通。这一步自己做，不拿去问用户。
  - 第 5 步给用户看：plan.md 多了“剩下读作”“风险”两列和一张重复句子表（进了连读待定的那几遍也在表里）。先贴重复句子表，再按四类贴，风险“高”的请用户重点听；五轮扫描.md 里犹豫过没删的，挑要紧的提一句。用户恢复了哪几条、补删了哪几处，验收后记进运行记录的误删、漏删。
  - 第 7 步字幕：make_subtitles.py 之后跑 `uv run python scripts/terms.py <文件夹>`，按术语表（设置里 glossary 列的，加视频文件夹里的 术语表.md）改错字，出 <运行>/subtitles_terms.json 和 修字表.md。拿 subtitles_terms.json 当底稿写 subtitles.json，规矩同第 7 步，只是没有讲稿可对，另外照这几条改：
    - 数量、时间、钱数、百分比写阿拉伯数字：“八个”写 8 个，“三分二十秒”写 3 分 20 秒，“百分之四十八”写 48%；“两”照写汉字（两个、两张）；“一”只在时间、钱数、和别的数连着时写 1（1 分 20 秒），“一个”“一张”“一段”照写；“一下”“一点”“一起”“第一”这类不是数量的、“五六秒”“九成”这类概数也照写汉字。
    - 说的是 AI、程序、工具、东西时写“它”，说人才写“他”“她”（转写一律出“他”）。
    - 同音错字按上下文改：比如“文件已经倒出了”写导出，“跑的很快”写跑得很快。读一遍整行，意思说得通才改。
    - 断行：没有讲稿可照，按阅读稿的停顿和意思断，一个词不要切在两行；只有一两个字的行并进前后行。转写自带的逗号、句号常标错位置，不照它断：先把整句读一遍，看每个字归前一截还是后一截，比如转写成“这周买了，两台电脑一台给我妈”，意思是“这周买了两台电脑 一台给我妈”，就按意思断。顿号和逗号一样换成空格；转写加的问号，不是问句就去掉。
    - 结巴没删、还留在声音里的（比如“聊聊一聊”），字幕写顺的说法；说断、重说进了连读待定留在声音里的，字幕照实际说的写（这几个字也进字幕）。
    - 修字表看一遍，改错的改术语表重跑。
    写完跑 `uv run python scripts/check_subs.py <文件夹>`，不用出视频就能查每个字是不是恰好在一行里、每行有没有超过 16 个字。术语表里没有、又听不出是什么的专有名词（店名、人名、产品名），不猜，照转写原样留着，列成“待确认的词”给用户。
  - 配素材（出成片时）：粗剪用户认可以后跑 `uv run python scripts/prepare.py --script-from-cut <文件夹>`，按定下来的字幕生成 work/讲稿_按转写.md（句号就是一句一个画面），写进 inputs.json 的 script，后面找素材、配素材照常用它。它没有镜头表，素材按句自己出清单，先列给用户确认（竖屏默认不配素材，见“竖屏”一节）。

## 竖屏

用户说要竖屏（抖音、小红书这类）时用：成片 1080×1920，没配素材的句子人脸全屏，配了素材的句子整屏换成素材，不叠小窗。默认关：不说竖屏就照旧出 16:9、左下角圆形小窗。
- 怎么打开：第 1 步加 `--vertical`，inputs.json 记 `"vertical": true`。已经建好的文件夹补跑一次 `prepare.py --video <原片> --vertical` 就会改上，从 compose.py 起重跑。原片竖的横的都行：竖的人脸整幅放大；横的按 9:16 裁一条，对着 work/pip.json 取景的中心（没有就取正中；横拍原片出竖屏只算过几何，没实际出过片，出完要仔细看）。
- 和 16:9 不一样的只有这几处，其余照常：
  - 默认整片人脸、不配素材（竖屏口播大多不要素材）：粗剪认可后不找素材，shots.json 每句 asset 写 `"人脸"`、effect 写“无”、不写 transition（人脸接人脸，程序默认硬切），接着写英文字幕、出预览。给用户看预览时提一句“哪几句想配画面可以说”，不主动列素材清单。没有讲稿的，--script-from-cut 照旧要跑（分句要用）。
  - 用户说要加素材（说了哪几句、想放什么，或者让 Claude 挑几句）：只给这几句写 素材/plan.json，放人脸的句子不写（fetch_assets.py 竖屏时不查这几句，会列出哪几句放人脸），照“找素材”一节取，素材清单先给用户确认；shots.json 里这几句写素材，其余照旧人脸。
  - 配素材（第 10 步）：放人脸的句子 asset 写 `"人脸"`、effect 写“无”（无人脸模式不能用）。横的素材（网页截图、横图、横视频）照 16:9 的动效做，放进竖屏中间、上下垫模糊的同一画面；竖的图片、竖的视频铺满竖屏（竖图写“模糊垫底”也按铺满做）。不写 work/pip.json 的 track，不看 小窗样帧.jpg（竖屏没有小窗；横的原片要对准人脸时，写 pip.json 的 crop 就行）。
  - 预览：预览.jpg 是竖的格子，一排四个。
  - 字幕：竖屏的字号和位置是 config.yaml 里 vertical_ 开头那几项，躲开平台界面挡住的地方（vertical_safe：顶部标签栏、底部账号文案、右侧按钮那一列）。每行仍不超过 16 个字。
  - 成片自检第 4 节查字幕有没有进平台界面挡住的地方，不查小窗。
- 无人脸模式也能出竖屏：没有人脸可放，照旧每句配素材，缺素材的句子黑底“待补素材”。

## 步骤

1. 准备：跑 `uv run python scripts/prepare.py --list`，把最新的 3 个原片（视频和录音都列，录音标“录音”）、找到的讲稿和默认名称列给用户，等用户选定（用户给了路径就用用户给的）；没找到讲稿时问用户有没有，没有就按“没有讲稿”一节加 `--no-script`。用户给的讲稿不是 docs/讲稿样例.md 的样子（没有“## 讲稿全文”一节、句子没按“1. ”编号，或者是 Word、纯文本），先照样例整理成一份 .md 放进视频文件夹，给用户看过再用 `--script` 指过去，意思和句子都不改。再跑 `prepare.py --video <原片> --script <讲稿> --name <名称>`，只用声音的视频加 `--no-face`（见“无人脸模式”一节），要竖屏加 `--vertical`（见“竖屏”一节），用户说节奏紧一点、停顿短一点加 `--pace 紧`（剪口和压过的停顿只留约 0.15 秒，标准约 0.3 秒；片头不带开口前的杂音）。原片不移动、不改名。
2. 预处理：`uv run python scripts/preprocess.py <文件夹>`。说是 HDR 就停，请用户关掉 iPhone 的“HDR 视频”重录（无人脸模式不查）。
3. 转写：`uv run python scripts/transcribe.py <文件夹>`。
4. 方案：读 work/transcript.md、work/transcript.json 的 tokens（每个字的序号 i）和讲稿全文（`prepare.py --script-text <文件夹>`），写 work/deletions.json：
   - 每条 `{"type": "语气词|说断|重说", "from_token": 起, "to_token": 止, "reason": "一句话理由"}`，序号含两端，时间不写。
   - “改稿”只用于用户要求删掉的内容（不是口误），比如出某个平台的专用版时要去掉的整句或词；Claude 不自己加。
   - 语气词：嗯、啊、呃，以及当口头禅用的“那个”“就是”。拿不准是不是口头禅的不删，在对话里提一句。
   - 说断和重说：同一句说了几遍，只留最后一遍完整的，前面说断的和完整的都删。对照讲稿判断哪几遍是同一句。
   - 讲稿里有、口播里没说的不管；口播里多说的、讲稿里没有的，不算重说，不删。
   - 跑 `uv run python scripts/plan_cuts.py <文件夹>`。校验不过就按报错改 deletions.json 重跑，最多 3 次，仍不过把报错交给用户。
5. 等用户确认：把 work/plan.md 按四类（语气词、重说、长停顿、连读待定）贴在对话里，每处有原话和时间，问“可以吗”。连读待定默认不删，逐处问用户。
   - 用户说某条不删、某处连读待定要删、某段停顿别压：写进 work/decisions.json，例子 `{"pending": {"59-59": "删"}, "deletions": {"46-47": "不删"}, "pauses_keep": [[17.2, 18.0]]}`。键是字序号范围，取值只有“删”“不删”；pauses_keep 是原片里的秒数范围。
   - 用户说某处空白太长（压过停顿还剩一两秒以上，多半是几段静音中间夹着碰麦、咔哒声，一段段压完还剩不少）：写 `"blank_cut": ["241-244"]`，两个字序号是空白前最后一个字、空白后第一个字，中间只能有要删的字。这段里的小杂音当静音，整段连成一处，剩约 0.3 秒，和别的接缝一样。不写秒数，脚本按转写的字算。
   - 用户要多删什么：加进 deletions.json。改完从 plan_cuts.py 重跑，再给用户看，直到用户回“可以”。
6. 剪辑表：`uv run python scripts/validate_edl.py <文件夹>/work/edl.json`，通过才往下。
7. 剪：
   - `uv run python scripts/cut_audio.py <文件夹>`（剪声音，再转写一遍复核，自动挪刀最多 3 轮）。
     复核报某个接缝旁多出字（替换），而那里正是用户选删的连读待定：多半是语气词和后面的字连着说、尾巴没切干净（演示片的“哎救不回来”就是这样，换 blank_cut 也没切净）。把这一点告诉用户，再出一版不删的粗剪给他对照，由他选。
   - `uv run python scripts/make_subtitles.py <文件夹>`，读 <运行>/subtitles_auto.json。
   - 对照讲稿写 <运行>/subtitles.json：`{"lines": [{"text": "…", "from_token": 起, "to_token": 止}]}`，不写时间。改认错的词（Astra、ChatGPT、Codex、越权、GPT-5.6 这类），数字按讲稿写（48%、10 月）；按讲稿的断句调整每行管哪几个字；每行不超过 16 个字（英文字母、数字两个算一个）；句末标点去掉，句中逗号换成空格，问号、书名号、引号保留。讲稿和实际说的不一样时，以实际说的为准。每个要进字幕的字恰好属于一行，顺序不变。
   - `uv run python scripts/render_rough.py <文件夹>`。字幕校验不过就按报错改 subtitles.json 重跑。
8. 自检：`uv run python scripts/check.py <文件夹>`。把 check_report.md 的开头、“程序查出的问题”和“要重点听的接缝”贴给用户，给出 <运行>/粗剪.mp4 和 接缝试听.mp4 的路径，再提一句同一个文件夹里有 粗剪.srt（字幕文件，可以导进剪映等软件或单独上传）。自检只报告，改不改由用户定。
9. 记录：`uv run python scripts/record_run.py <文件夹>`（它会打印记在哪个文件）。用户验收后，把运行记录里的“待填”补上。

## 出成片（粗剪用户认可之后）

设置了 finish_standard（用户自己写的成片标准，写了通配就取日期最新的一份），成片照它做，下面没写到的细节以那份为准。没设就照默认做：中英字幕、左下角圆形小窗、一句一个画面、按段落转场、平缓的背景音乐，细节照下面写的。

10. 配素材：读 work/transcript.json、讲稿全文、素材/assets.json 和 素材/预览.jpg（逐张看自动拿到和用户补的素材），写 work/shots.json：讲稿每句一条，写这句在转写稿里的字序号范围、用哪项素材、动效、一句看过素材后的描述（格式见 scripts/compose.py 开头）。网页截图默认用截图聚焦，AI 图和图库图片用推拉，竖图和长图用模糊垫底，视频只能铺满；素材说明里写了不能裁、不能推拉的图（比如苹果新闻稿配图）用“无”。推拉会裁掉四边一点：图里有黄框的，程序自动让框留在画面里；别的必须留住的地方（贴着边的字、图表）写 params.keep（格式见 compose.py 开头）。有人脸小窗时（无人脸模式跳过这一段），第一次还要看 小窗样帧.jpg，写 work/pip.json 让人脸在小窗正中。录的时候坐姿前后有变化（固定取景顾了开头顾不了后面），跑 `uv run python scripts/pip_track.py <文件夹>`：每 0.5 秒用 macOS 的 Vision 找一次脸，平滑后写进 pip.json 的 track，小窗跟着脸走；看 <运行>/小窗跟踪.jpg 核对，再从 compose.py 起重跑。
    - 16:9 全屏出镜的句子（plan.json 写了 face 的）：asset 写 `"人脸"`、effect 写“无”，这句整屏放原片画面、不叠小窗（无人脸模式不能用）。face 里的句子没写“人脸”、写了“人脸”的句子不在 face 里，compose.py 都会报错。连着几句人脸默认硬切；和配素材的句子之间照常转场，小窗在转场里跟着淡出淡入。横拍原片（手机横放录的）没写 pip.json 时小窗取画面正中一块，脸常常偏小，照上面看 小窗样帧.jpg 写 pip.json 或跑 pip_track.py。
    - 转场：讲稿分了段落的，按段落给每句写 transition（溶解、滑入、擦除、圆形展开、柔和推移、无），同一段落用同一种，相邻段落换一种；讲稿没分段就不写，程序逐句轮换。太短的句子程序自动改硬切。
    - 背景音乐：设置了 default_bgm_dir（用户常用的背景音乐），就从那个文件夹复制 bgm_1_*、bgm_2_*……和 bgm.json 到新视频的 素材/，把 bgm.json 的获取日期留原样；没设就照下面“想换时”挑。想换时：按讲稿的调子从免费可商用曲库（Mixkit 等，许可写明可用于社交平台视频）挑 3 首，把曲名、作者、时长、试听链接列给用户。用户选定后，说明要下载的文件名、来源和大小，用户同意再下载到 <文件夹>/素材/bgm.<扩展名>，写 <文件夹>/素材/bgm.json：`{"title": "曲名", "author": "作者", "url": "曲子的页面", "license": "许可名称", "date": "获取日期"}`。用户选了几首轮流放时，文件存成 bgm_1_<曲名>.mp3、bgm_2_<曲名>.mp3……，bgm.json 写 `{"tracks": [{"file": "bgm_1_….mp3", "title": …, "author": …, "url": …, "license": …, "date": …}, …]}`，按用户说的顺序放，默认整首放完换下一首；用户要每首放一段就换（比如两首各 30 秒轮流，再轮到时接着放），bgm.json 再加 `"switch_seconds": 30`。每段长短不一样的写成一串，比如 `"switch_seconds": [120, 120, 120, 60]`：前三段各 120 秒，之后每段都按最后一个数 60 秒。用户自己下好的，复制过来，原件不动。曲库网站要人机验证就换一家，不绕过。用户说不要音乐，就不放 bgm 文件。
    - 英文字幕（默认加，用户说不要才不加）：compose 之前，在 <运行>/subtitles.json 每行加 `"en": "……"`，一行中文对一行英文，口语、简短，术语照原样（Claude Code、FunASR），剪映写 CapCut。render_final.py 会把英文用小一号的字放在中文下面；只写了一部分会停下。粗剪不出英文。
11. 预览：`uv run python scripts/compose.py <文件夹>`。缺素材时它会停下列出缺哪几句；用户要先看效果就加 --draft。把 <运行>/预览.jpg 给用户看，用户说可以再往下。
12. 成片：`uv run python scripts/render_final.py <文件夹>`，然后 `uv run python scripts/check_final.py <文件夹>`。镜头表要求插入旧片段（带原声）的，skill 出片后照设置里 insert_clip_example 那份脚本的做法用 FFmpeg 拼（改切点句号、片段路径和帧数；没设就先跟用户说打算怎么拼），插入后紧接的那句在 shots.json 里写 transition“无”；来源清单要把旧片段用到的来源也并进去。把 成片自检.md 的问题和第 2 节那张表贴给用户（用户据此数配错几句），给出成片路径、和成片同名的 .srt（中英字幕，平台单独上传字幕时用）和 来源清单.md（画面上不标来源，发布时贴进简介，背景音乐也在里面）。请用户听一下人声清不清楚：音乐嫌大嫌小，在 config.local.yaml 里写 bgm_lufs（默认 -32，数越小越轻；写在本机那份，不改进仓库的 config.yaml），只重跑 render_final.py 和 check_final.py。用户认可后把成片复制到 <文件夹>/成片/。

## 导到剪映（用户说要在剪映里接着改时）

粗剪用户认可以后可以导：跑 `uv run python scripts/export_jianying.py <文件夹>`，把剪好的画面段（从原片截、带原声）和字幕写成一个新的剪映草稿，原片复制进草稿自己的文件夹。字幕只有中文；出过成片、subtitles.json 每行都有英文的，再多一条英文字幕。配的素材、转场、背景音乐不进草稿。
- 第一次导之前先跟用户说一声：会在剪映的草稿文件夹（默认 ~/Movies/JianyingPro/User Data/Projects/com.lveditor.draft）里新建一个叫“<文件夹名>_粗剪”的草稿，并复制一份原片（说多大），用户同意再跑。草稿文件夹不在默认位置的，加 `--drafts <文件夹>` 或在 config.local.yaml 写 jianying_drafts。
- 同名草稿已经有了它会停下，不覆盖：换个名字加 `--name`，或者请用户先在剪映里删掉旧的。
- 它写完会把草稿读回来和剪辑表、字幕逐段比，最后一行写“逐段比过”才算导好；然后请用户打开剪映专业版看。这是非官方功能，剪映升级后可能打不开，打不开就说明这一点，不去改剪映自己的文件。

## 改了怎么重跑

- 用户按时间说要改哪里（“第 23 秒那张图换掉”“1 分 05 秒那行字幕错了”）：先跑 `uv run python scripts/locate.py <文件夹> <时间>`（秒数或分:秒，可以一次给几个），它报那一刻是第几句、用的哪项素材、哪行字幕、在 shots.json 和 subtitles.json 的第几条、改完从哪步重跑。只读它指出的那几条再改，不通读文件；它提示“改过还没重跑”的，时间按上次出片算。
- 用户说要改哪条删不删、哪段停顿压不压：改 deletions.json 或 decisions.json，从第 4 步的 plan_cuts.py 起重跑。
- 嫌剪口、停顿空得久：补跑 `prepare.py --video <原片> --pace 紧`，从 plan_cuts.py 起重跑（字幕的字不用重写，subtitles.json 照用，从 make_subtitles.py 那步把它放回新的运行目录）。
- 只改字幕：改 <运行>/subtitles.json，从 render_rough.py 起重跑，再跑 check.py；出过成片的，再从 compose.py 起重跑。
- 只改配素材、动效或转场：改 work/shots.json，从 compose.py 起重跑。
- 只换背景音乐或改音量：换 素材/bgm.* 和 bgm.json，或改 config.local.yaml 的 bgm_lufs，从 render_final.py 起重跑。
- 出某个平台的专用版（比如小红书不让出现别的平台和品牌名）：把视频文件夹复制一份，名称后加“_<平台>版”，原版不动；用户要删的整句或词加进 deletions.json，type 写“改稿”，reason 写清哪个平台、谁定的；从 plan_cuts.py 起重跑，字幕从原版的 subtitles.json 去掉删了的行再改。整句删比单删几个字稳：词和前后连着说时切不干净。画面上的品牌名和网址打码、换掉有品牌标志的画面，做法和脚本见设置里 platform_version_tools 指的文件夹（设了才有）。
- 转写有缓存，不会重跑。

## 硬规则

- 删什么只由用户确认过的方案决定。复核只挪刀，不改删什么。
- 刀点、时间、帧号全由脚本算，Claude 不写、不估。edl.json 只由 plan_cuts.py 生成，不手改；plan_cuts.py 说 edl.json 被改过，就停下问用户。
- Claude 写的 deletions.json、decisions.json、subtitles.json 都要过脚本校验才算数。
- 不删任何运行结果，失败的也留在 runs/ 里；原片只复制不移动。视频发布、用户备份了成片以后，设置了 cleanup_guide 就照它指的说明清理大文件，要用户同意，挪进废纸篓不直接删。prepare.py 只在 videos_root 顶层找已有的文件夹，清理时挪进子文件夹的那期要接着剪（比如出别的平台版本），先把它挪回顶层。
- 不做：自动调用 AI 生图、画面上标来源（来源写进来源清单，发布时贴进简介）、视频素材加动效、三种以外的动效、音乐随人声自动压低、按节拍换画面、不经用户同意下载音乐、降噪；用户要的话，说明现在不支持，不临时加。
